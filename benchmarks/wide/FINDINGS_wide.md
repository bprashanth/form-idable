# Wide cross-sector form-transcription benchmark — findings

**Dataset:** 17 forms across 8 sectors under `benchmarks/wide/forms/`:
- **9 synthetic Indian social-sector forms** (school attendance, exam marks,
  anganwadi growth monitoring, PHC immunization session, OPD register, child
  vaccination cards ×2-per-page, SHG savings ledger, MGNREGA muster roll,
  kharif crop survey) generated by `gen/formgen.py`: printed structure +
  handwriting-font fill with per-char jitter + scan-noise pipeline. Goldens are
  **exact by construction**. Layout variety: portrait/landscape, dense tick
  grids, tallies, checkboxes, decimals, rupee amounts, dot=0 / strike=blank
  notation, marginal notes, multi-form-per-page, 2-page forms.
- **3 hard variants** (messy cursive fonts, 0.72× resolution, heavy
  blur/noise/JPEG) — graded "readable with effort" by an independent review.
- **4 real scanned forms** from FUNSD (corporate suggestion, CAPRI finance
  ledger, lab test receipt, engineering change request) — real handwriting on
  real photocopies; goldens hand-verified and corrected (FUNSD's own
  annotations misread several cursive fields — see each form's provenance.md).
- **TreePlots** (Western Ghats tree-plot survey) as the known anchor from
  `FINDINGS_treeplots.md`.

**Scoring:** same tolerant `xlsx_diff` recall as the nightly regression, plus
**precision and F1** (`wide_diff.py`) closing the known over-production blind
spot. num_f1 is the headline metric. One run per config; treat differences
under ~0.05 as noise (codex run-to-run variance).

**Total API spend: ~$0.65** (budget $20).

## Recommendations

### (a) No privacy constraint — cheapest API with best performance

**Default: `gemini-2.5-flash`, oneshot, reasoning off — numF1 0.90 at
$0.0013/form, 5 s/form.** It is the best score on real scans among APIs
(0.85), the word-F1 leader, and 30-50× cheaper than codex-class agentic runs
at equal-or-better accuracy than every other cheap option.

- If quality is worth 5× the price: **gemini-3.6-flash tiled** (0.93 overall,
  best synthetic-sector score 0.97) at $0.008/form — still trivially cheap in
  absolute terms (1,000 forms ≈ $8).
- Google-free / open-weight: **gemma-4-26b-a4b-it via OpenRouter** at
  $0.0003/form matches 2.5-flash overall (0.89) but gives up ground on real
  scans (0.80); qwen3-vl-32b (0.88, $0.0005) is the strongest non-Google
  real-scan alternative (0.78).
- **Textract** (0.89 overall, 0.84 real, precision 0.95) is a serious non-LLM
  option but 13× the price of gemini per form and it cannot apply notation
  rules (dot=0, tallies) — use only if "no LLM" is itself a requirement.
- Mode choice: **tiling only pays when the scan's native resolution exceeds
  the ~1568px vision cap** (TreePlots: +0.11 num recall). For ≤150 DPI scans
  (all FUNSD forms) oneshot is equal or better and cheaper. Prod should pick
  per-document: tile iff render caps out.

### (b) Privacy constraint — best local/on-prem

**Default: Qwen3-VL-8B-Instruct-FP8 on the GB10 via vLLM — numF1 0.89
(oneshot), within noise of gemini-2.5-flash, at $0 and zero data egress.**
27-38 s/form single-stream on this box (batching brings this down; the GPU sat
mostly idle at bs=1). Notably it *beats* the same model served by OpenRouter
(0.85) — likely provider-side image downscaling — so local serving is not a
compromise, it is slightly better.

- **DeepSeek-OCR (3B)** at 8 s/form scores 0.82 overall / 0.90 synthetic with
  the highest precision (0.96) — but 0.66 on real scans, and it cannot follow
  notation instructions (tallies/checkbox semantics are lost: immunization
  0.67, engineering 0.60). Answer to "would the peanut OCR model work": as a
  standalone, **no** for our hard cases; as a fast high-precision first pass on
  clean printed+neat-hand forms, yes.
- Stock qwen3-vl-2b is unusable (0.48; 9/17 runs degenerate into repetition
  loops until the token cap).

### (c) Can the private option be trained up to API level? — YES (with one gap)

We LoRA-fine-tuned qwen3-vl-2b (r=16, attention+MLP, vision tower frozen,
2 epochs, ~12 min on the GB10) on **180 synthetic forms** (seeds 100-109,
generated by the same `formgen.py` — eval seed 7 disjoint; real forms fully
held out). Result:

| qwen3-vl-2b | overall numF1 | REAL | SYN | degenerate runs | sec/form |
|---|---|---|---|---|---|
| stock | 0.46-0.48 | 0.22-0.30 | 0.52-0.59 | 9/17 | ~110 |
| **+ LoRA (tiled)** | **0.88** | **0.70** | **0.96** | **0/17** | **11** |

- **Overall it now matches the local 8B (0.88) and gemini-2.5-flash-tiled
  (0.89)** — a 2B model, 11 s/form, zero cost, zero egress. The repetition
  collapse is gone entirely and word F1 (0.90) is the best of any local model.
- **In-domain (synthetic layouts) it is near-perfect (0.96)** — better than
  every API model except gemini-3.6-flash.
- **The remaining gap is real handwriting**: 0.70 vs the 8B's 0.75-0.80 and
  gemini's 0.85. Training was synthetic-only; the model more than doubled its
  real-scan score (0.30→0.70) purely from format/task transfer, but messy real
  cursive needs real examples.

**Conclusion: the path to a private model that matches the API winner is
real training data, not more compute.** The recipe is proven and cheap
(`formgen.py` → `make_sft.py` → `train_qwen3vl_lora.py`, minutes per run).
When partners contribute real scans, golden them (the SNAPSHOT.md method) and
add them to the SFT set; expect the 0.70 real-scan number to climb toward the
synthetic 0.96. Meanwhile the 8B off-the-shelf is the safe private default,
and the tuned 2B is the cheap-hardware option (it would run on far smaller
devices than this GB10).

## Caveats (honest limits)

- **One run per config.** codex itself varies ±0.05; differences below that
  are noise. Rankings separated by ≤0.02 are ties.
- **Synthetic handwriting is easier than real.** Handwriting fonts + jitter +
  scan noise did not fool codex (1.00 synthetic vs 0.91 real). The synthetic
  half measures format-following and layout robustness; the real half carries
  the handwriting difficulty. Grow the real side.
- **FUNSD goldens were corrected by a model reviewer** (Sonnet-class) against
  the scans; residual golden errors possible on the hardest cursive (one
  illegible signature and one ambiguous change-order number were excluded).
- **codex ran on a 6-form subset** (3 synthetic + treeplots + 2 real/hard) —
  its 0.97 average is over an easier mix; on the shared real forms it scored
  0.83 (treeplots) and 1.00 (lab receipt).
- **DeepSeek-OCR needed its native transformers path** (vLLM chat endpoint
  mistokenises it in this nightly build); latency measured there.
- Textract latency includes network to ap-south-1; its $/form is 1 page
  ($0.015) to 3 pages ($0.045) at the TABLES rate.
- Excluded rows: gemini-2.5-flash-lite (retired for new users, HTTP 404);
  transient OpenRouter failures were retried and back-filled.

## Reproduce

```
cd benchmarks/wide
python3 run_suite.py --configs configs_api.json          # API sweep
./serve_local.sh qwen8b && python3 run_suite.py --configs configs_local_8b.json
python3 run_codex.py forms/<form> ...                    # agentic baseline
python3 rebuild_results.py && python3 analyze.py         # tables
```
Keys in `~/.config/formidable/`; local models in `~/models/wide-bench/`.
